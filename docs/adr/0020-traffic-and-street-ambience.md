# ADR 0020: 交通与街区底噪

**日期**: 2026-08-14
**状态**: Accepted
**修正**: ADR-0009、ADR-0013 中演出锁定对持续世界危险的适用范围

---

## 背景

主路线包含需要玩家判断信号并横穿道路的场景。街道还需要持续的空间听觉反馈，使玩家在接近道路时能够感知交通环境。交通危险必须来自真实移动的车辆，而不能把“行人红灯”直接等价为死亡；与此同时，玩家按快速提示音合法进入横道时，应获得尽可能安全、可理解的通行窗口。

## 决策

### 独立过街点与信号周期

使用 **交通过街点 (Traffic Crossing)** 表达一个独立工作的路口。每个过街点拥有自己的信号周期、提示音位置、车辆停止线、车辆清空检测区和交通复活点，不依赖玩家靠近才启动或重置。

内部信号采用三个阶段：

1. **车辆通行期 (Vehicle Flow)**：对玩家表现为行人红灯，播放较慢提示音，车辆可以通行。红灯代表真实车流风险，但只有车辆实际碰撞才会伤害玩家。
2. **车辆清空准备期 (Vehicle Clearing)**：仍播放较慢提示音。能够在停止线前平稳停车的车辆减速停车；已越线或来不及停车的车辆承诺通过，并以不超过 `6 m/s` 的目标速度尽快驶离横道。车辆清空检测区无车后才能进入行人绿灯。
3. **行人绿灯期 (Pedestrian Green)**：播放较快提示音，停止线前车辆保持停车。绿灯持续时间由原来的 `8` 秒增加为 `16` 秒。

行人绿灯结束后立即回到车辆通行期，不增加全局行人清空锁。车辆获得起步许可后仍必须先检查自身前方检测走廊：前方有玩家时继续停车，直到走廊连续空闲 `0.5` 秒才起步。信号计时独立于玩家阻车，不因车辆被玩家挡住而暂停或重置。

快速提示音只能在车辆清空检测区确认为空后开始。车辆清空准备期不播放第三种玩家提示音，避免诱导玩家提前进入道路。正常游玩不显示常亮的红/绿发光面，避免在黑暗中绕过感知系统泄露交通状态。

本轮只在 `scenes/main/Main.tscn` 的主路线第一次过街位置接入完整交通系统，对应现有 `DialogueTriggers/Crosswalk` 附近。其他斑马线和静态车辆仍作为装饰。

### 车辆运动与行人避让

**交通车辆 (Traffic Vehicle)** 沿固定车道路径循环移动，不引入物理驾驶、导航寻路、换道或复杂避让。本轮每条车道最多一辆动态车辆。

车辆保留 `STOPPED`、`STARTING`、`RUNNING`、`BRAKING` 运动状态，但避让结果由实际速度、玩家距离和制动能力决定，而不是由状态名称直接决定。初始调试参数为：

- 巡航速度 `5 m/s`，清空目标速度 `6 m/s`。
- 起步加速度 `2 m/s²`。
- 信号减速度 `3 m/s²`。
- 紧急制动力 `5 m/s²`。
- 车辆本地前方检测走廊长 `6 m`、宽 `2.7 m`。

前方检测走廊和实际碰撞必须分离：

- `ForwardDetection` 只负责发现玩家、鸣笛和制动，不造成伤害。
- `ImpactArea` 紧贴车身，只在玩家真实接触车辆时结算冲击。
- `PhysicalBody` 负责实体阻挡。

运行车辆发现玩家后立即鸣笛并紧急制动；制动距离不足时仍可能发生碰撞。停止车辆只有在获得通行许可后才因玩家阻挡鸣笛：首次阻挡立即鸣笛，之后每 `2–3` 秒重复一次。行人绿灯或车辆清空准备期内，依法停车的车辆不得向合法过街玩家鸣笛。车辆不会因等待过久而强行起步。

承诺通过车辆的清空优先级不能覆盖行人避让。玩家进入其检测走廊时，车辆仍须鸣笛和紧急制动；车辆停在清空检测区内时，行人绿灯继续等待。

### 车辆冲击

车辆碰撞不再固定清空 HP，而是按碰撞瞬间的水平相对速度计算：

`damage = round(4 × impact_speed²)`

其中 `impact_speed` 是车辆与玩家的水平相对速度。典型结果为 `1/2/3/4/5 m/s -> 4/16/36/64/100` 点伤害。伤害达到玩家剩余 HP 时进入既有死亡和失败流程；否则按伤害等级进入身体反馈：

- `1–9`：轻踉跄。
- `10–35`：失衡踉跄和既有恢复 QTE。
- `36–99`：直接摔倒。
- 致死伤害：死亡优先，不进入 QTE。

撞击位移方向采用水平相对速度方向，距离采用线性并封顶的规则：

`distance = clamp(0.35 × impact_speed, 0, 2.0)`

位移由 `GaitController` 在短时间内通过 `move_and_slide()` 完成，不直接传送玩家。车辆撞击伤害每次连续接触只结算一次；玩家与同一车辆持续分离至少 `0.3` 秒后，下一次接触才可重新结算。不同车辆分别计算。

非致死撞击本身不重复计算为摔倒首帧伤害；如果玩家随后在不稳定地形继续滚落，仍按既有滚落规则追加伤害。运行车辆碰撞后继续紧急制动，完全停止后在玩家离开前保持停车，不模拟碾压、拖拽或持续接触伤害。

致死碰撞记录碰撞位置附近最近的显式 **交通复活点 (Traffic Respawn Point)**。玩家在失败演出中选择重生后移动到该道路边安全位置。

### 车辆与街区声音

每辆动态车辆需要可定位的 3D 循环行驶声：停止时保留较弱怠速，音量或音高随速度平滑变化。鸣笛使用独立的 3D 音效，不能复用红绿灯提示音或通用危险提示音。正式素材缺失时允许使用语义独立的占位音验证逻辑。

街区底噪区循环播放 `assets/audio/sfx/street_ambience.ogg`。底噪音量根据玩家到街区区域的距离连续衰减：区域内保持正常音量，离开后逐渐降低，超过衰减距离后静音。底噪不能替代具体车辆的方向和距离反馈。

交通信号、车辆、提示音、车辆声和街区底噪在叙事播放期间继续运行。车辆冲击只以游戏是否处于 `PLAYING` 为准，不以玩家能否输入为准；致死逻辑优先于叙事。

## 职责边界

- `TrafficCrossing`：信号周期、车辆清空检测区和停止线通行许可。
- `TrafficVehicle`：车辆运动状态、前方检测、鸣笛、车辆声、当前速度和单次接触锁。
- `TrafficSystem`：平方伤害、交通死亡和道路边复活。
- `GaitController`：外部冲击导致的踉跄、摔倒和物理位移。
- `PlayerAttributes`：HP 数值和死亡事件，不理解交通规则。

## 非目标

- 不把全部装饰斑马线、交通灯和静态汽车自动转换为交通系统。
- 不实现同车道多车、跟车、排队、追尾、换道、拥堵模拟或随机路线。
- 不实现行人红灯的隐形墙、强制输入锁、信号判死或玩家无敌。
- 不修改 KayKit 原始车辆和交通灯资源。
- 不引入全局交通单例。

## 考虑的替代方案

| 方案 | 否决理由 |
|------|---------|
| 行人红灯直接致死 | 危险脱离真实车辆位置，玩家无法通过声音和时机判断风险 |
| 只延长行人绿灯 | 绿灯末尾边界始终存在，不能解决车辆起步时玩家仍在前方的问题 |
| 玩家位于整个横道时冻结全部车辆 | 玩家可以在无冲突位置阻塞所有车道，红灯也会失去风险 |
| 固定等待若干秒后宣布绿灯 | 无法适应车辆减速、被玩家阻挡或停在横道内的实际状态 |
| 检测距离随车速变化 | 混淆车辆感知范围和制动距离；检测走廊应固定，速度只影响能否停住 |
| 叙事锁定时暂停交通世界 | 街边剧情会让车辆和环境声突然消失，并允许剧情成为规避危险的手段 |

## 验收要求

实现阶段不能只启动游戏确认无报错。除持久化行为测试外，还需要在 `scripts/debug/` 添加临时测试脚本控制玩家并跟踪 Godot 输出，至少确认：

- 车辆清空前不会播放快速提示音；横道清空后才开始完整 `16` 秒绿灯。
- 绿灯期间车辆停车，检测到合法过街玩家也不鸣笛。
- 红灯放行后，前方有玩家的车辆保持停止并周期鸣笛；玩家离开 `0.5` 秒后才起步。
- 运行车辆遇到远处玩家能够制动停车，遇到近处玩家会减速但仍可能碰撞。
- `1–5 m/s` 相对速度产生约 `4/16/36/64/100` 伤害。
- 非致死碰撞触发对应踉跄或摔倒，并产生速度相关位移。
- 同一次持续接触只扣血一次，分离后重新接触才再次结算。
- 致死碰撞进入失败流程，并在最近道路边复活。
- 车辆行驶声和鸣笛声能随具体车辆产生方向与距离变化。
- 玩家接近街道时能听到底噪，远离后连续衰减到静音。
- 叙事锁定期间信号、车辆及所有交通音频继续运行。
- 临时测试脚本完成后必须移除。
